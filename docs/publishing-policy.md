# Publishing policy

The public edition is a sanitized projection. Full-fidelity authoring and personal state remain outside it.

| Class | Public treatment |
|---|---|
| Reusable procedure or generic runtime code | Publish after removing identifiers, private examples and unavailable configuration dependencies. |
| Personal workflows, voice, editorial work, administration and teaching | Exclude the complete category, including related skills, templates, examples and records. |
| Project, course, financial or institutional records | Exclude. |
| Tests and examples | Use invented data and temporary paths; exclude captured operational transcripts and identifiers. |

The decision is substantive. The seven retained skills are technical/source methods; a useful-looking generic rewrite does not override an excluded category. A missing tier field is not a publication decision. Apply the same boundary to every historical version and archive.

Projection must preserve meaningful evidence and authority requirements. Replace a private dependency with an explicit configuration contract or a useful generic template. Do not quietly remove a required check to make a skill appear self-contained.

Use a finite file manifest and record source identity. Review the entire candidate tree, including hidden files and auxiliary assets. Scan history separately before making an existing repository public; a clean current tree does not sanitize earlier commits.

Exclude credentials, local configuration, knowledge snapshots, mail/calendar records, personal documents, host identities, release backups and operational fixtures. Pattern replacement is a backstop, not a substitute for review.

An explicitly commissioned scientific evidence archive is reviewed separately. Preserve original files privately. Where a record contains private values, publish a labelled derivative with original identity commitments, an exact redaction inventory and independent public hashes. Do not represent a redacted hash chain as the unchanged original. Personal workflow material remains excluded even when referenced by a scientific source manifest; retain only its hash commitment where needed to disclose that boundary.

Update the catalog and setup documentation whenever a public skill changes behavior. Public edits must be reconciled into the canonical projection source so regeneration preserves them.
