# Features and limits

| Component | Included behavior | Required setup or limitation |
|---|---|---|
| Technical/source methods | Conversion, acquisition, scientific reading, annotation recovery, literature survey and graph/semantic retrieval. | A method uses available tools; its presence does not install a connector or grant access. |
| Dual-runtime procedures | Shared `SKILL.md` contract and auxiliary assets. | Host discovery and tool support must be verified separately. |
| Routing and rooms | Configured role selection, room requests and dispatch integration. | User role/model registries and compatible host controls are required. |
| Amplifier runner integration | Constrained graph execution connected to Praxis agent contracts and Orca worker operations. | Not every skill needs a graph; not every requested effect has a supported adapter. |
| Hash ledger and traceability | Links among source/code identity, execution identifiers, receipts and output bytes. | Matching hashes establish identity/integrity, not factual correctness or substantive acceptance. |
| Evidence projection | Source/occurrence identities and durable records of reported outcomes. | Receipt ingestion does not revalidate every historical artifact or prove delivery. |
| Deep Research / Fact Check | Source acquisition and output-contract components. | Live execution needs engine, host and registry configuration. Unreachable or unread sources remain gaps. |
| Adaptive workflows | General native tasks for documents, editable decks, code/tests and websites; explicit publication with independent readback; retained outputs, immutable reference inputs and settled-check reconciliation. | Requires configured native seats, host tools and request-bound assignments. Running graphs remain fixed; fresh continuations retain completed work. No automatic retries or upstream checkpoint resume. |
| Test material | Reusable checks and synthetic examples selected for publication. | Private live-run transcripts, fixtures and deployment receipts are excluded. |

The functional fact-check path checks a bounded number of claims. Additional claims must remain visible as unchecked rather than disappear. Coverage measures and helper logs are evidence about the defined checks, not guarantees of truth or comprehensive research.

Publication does not establish successful installation, current model availability, native-host qualification, working schedules or acceptance of every workflow. Validation results should name the exact candidate, environment and checks. Do not promote a passing unit test or a successful worker to a stronger claim.

This edition excludes personal workflows and their related skills, along with private institutional knowledge, correspondence, profiles and account configuration. These exclusions apply to historical artifacts as well as the current package.

General task scopes are trusted coordinator instructions, not an OS sandbox.
Format checks establish file structure, while visual and substantive acceptance
need task-specific checks. Publication readback verifies declared bytes or a
stable marker at the exact destination; it does not establish every aspect of a
hosted application's behavior. Credentials stay in existing host tools. See the
[general task guide](../services/praxis45/ADAPTIVE-TASKS.md).
